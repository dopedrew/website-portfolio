Why I Built My Own Threat Intel Platform Instead of Paying for One

Every commercial threat intel feed I have used shares the same flaw: it tells you a CVE exists, not whether it matters to you. You get a CVSS score, a vendor advisory, maybe an EPSS number if you pay for the tier that includes it, and then the real work starts somewhere else, in a spreadsheet, in a ticket, in someone's head.

I wanted a system that collapsed that gap. Something that pulled from the same raw sources the commercial platforms pull from, CISA KEV, VulnCheck, NVD, GitHub Advisories, abuse.ch's malware and botnet feeds, OSV, and then did the part that actually takes judgment: is this exploited, is this on something I run, and has anyone told me about it yet.

So I built one. It now tracks 194,000 vulnerabilities, 183,000 of them with an EPSS score attached, and matches them against a small set of assets I actually watch. It is not trying to compete with Recorded Future or Mandiant Advantage. It is trying to answer one question fast: out of everything that happened in security today, what should I actually look at.

The honest reason I built it myself instead of buying one: the interesting part of threat intel is not the data, it is the judgment layer on top of the data, and that layer only gets good when you are the one who has to live with its false positives. A vendor tunes their alerting for a thousand customers. I only have to tune mine for me, which means I can afford to be aggressive about cutting noise in a way a platform selling to an enterprise SOC cannot.

This series is the build log. Ingestion, scoring, enrichment, asset matching, the alert engine, a real gap I found between CISA's KEV catalog and VulnCheck's, an attack map built from my own honeypot traffic, SBOM import, and what a year of running this in production actually taught me. All of it running on hardware in my own house, mostly in Python, feeding a PostgreSQL database nobody else has access to.
